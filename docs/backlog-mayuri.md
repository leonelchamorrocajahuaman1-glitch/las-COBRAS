# Backlog de trabajo – Rama Mayuri

## 1. Regla base
- trabajar solamente en la rama Mayuri,
- mantener documentación actualizada,
- hacer tareas pequeñas y medibles,
- usar la IA como apoyo para codificar cada tarea,
- probar cada mejora antes de seguir.

## 2. Objetivo
Mejorar la experiencia de adopción y dejar una versión más clara, útil y profesional de la plataforma.

## 5. Flujo de trabajo
1. seleccionar una tarea de prioridad alta,
2. revisar el contexto del archivo afectado,
3. pedir ayuda a la IA para una solución concreta,
4. probar la mejora,
5. corregir errores,
6. hacer commit,
7. continuar con la siguiente tarea.
